QA HANDOFF - SEMANA 01

Objetivo
Validar que los flujos implementados en Semana 1 están operativos y listos para pruebas funcionales.

Alcance tecnico cubierto por Web Dev
1) CMS-01 a CMS-04 implementados.
2) FE-01 a FE-03 implementados.
3) FE-04 fetchers tipados con fallback seguro.
4) API de leads con anti-spam y enrutamiento por tipo de formulario HubSpot.

Rutas a probar
1) / (home)
2) /villas
3) /villas/[slug]
4) /retiros
5) /solicitud
6) /styleguide
7) /api/lead

Casos de prueba criticos
1) Navegacion global
- Dado que entro al sitio
- Cuando hago click en cada item del header
- Entonces la ruta carga sin error y mantiene layout consistente

2) Carga de listados desde WordPress con fallback
- Dado que WordPress responde
- Cuando abro /villas y /retiros
- Entonces veo contenido
- Si WordPress falla, no debe romper la pagina (arreglo vacio o mensaje seguro)

3) Formulario solicitud - tipo solicitud
- Dado que completo nombre/email/mensaje y tipo Solicitud de Villa y Boda
- Cuando envio
- Entonces responde exito y crea submission en form SolicitudVillayBoda-WebDev

4) Formulario solicitud - tipo retiro
- Dado que completo nombre/email/mensaje y tipo Retreat Host Questionnaire
- Cuando envio
- Entonces responde exito y crea submission en form RetreatHostQuestionnaire-WebDev

5) Formulario solicitud - tipo waitlist
- Dado que completo nombre/email/mensaje y tipo Pop-up Hotel Waitlist
- Cuando envio
- Entonces responde exito y crea submission en form PopUpHotelWaitlist-WebDev

6) Anti-spam honeypot
- Dado que el campo oculto website contiene texto
- Cuando envio
- Entonces API responde ok sin crear lead real

7) Anti-spam por tiempo minimo
- Dado que envio antes del tiempo minimo
- Cuando API procesa
- Entonces responde ok y descarta envio

Variables requeridas para pruebas
1) HUBSPOT_PORTAL_ID
2) HUBSPOT_FORM_ID_SOLICITUD
3) HUBSPOT_FORM_ID_RETIRO
4) HUBSPOT_FORM_ID_WAITLIST
5) LEAD_MIN_SUBMIT_SECONDS
6) WORDPRESS_API_URL

Resultado esperado de build
npm run build debe finalizar sin errores.

Riesgos conocidos
1) Bloqueos de features premium dentro de HubSpot UI no afectan el endpoint de forms.
2) Si .env.local no tiene las 3 variables de forms, /api/lead devuelve 500 por config faltante.
